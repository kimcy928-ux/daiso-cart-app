# 다이소 장바구니

다이소 가기 전에 살 물건을 정리하는 개인용 PWA 앱입니다.
이름만 검색하면 다이소몰에서 사진/가격/품번을 가져와 장바구니에 담을 수 있고,
폰에 "앱처럼" 설치해서 쓸 수 있습니다.

## 만들어져 있는 기능

- 검색해서 담기 (다이소몰 실시간 검색, 로그인 불필요)
- 장바구니 목록 (사진/이름/가격/품번/수량 +,- /예상 합계)
- 샀으면 체크 → 2초 뒤 자동 삭제, "되돌리기" 가능
- 카톡 공유용 텍스트 복사 버튼
- **👥 친구랑 같이 쓰기**: 헤더의 👥 버튼을 누르면 공유 링크가 복사됩니다. 그 링크를
  카톡으로 친구에게 보내면, 둘이 같은 장바구니를 보면서 몇 초 안에 서로 담은 게 상대방
  화면에도 자동으로 뜹니다 (새로고침 필요 없음). 로그인 없이, 링크를 아는 사람끼리만
  공유됩니다.
- 새로고침/재접속해도 목록 유지 (휴대폰 로컬 저장, 공유 중일 땐 서버에도 저장)
- 홈 화면에 추가하면 앱처럼 열리는 PWA
- 다이소몰 응답이 이상해지거나 검색이 안 돼도 앱이 죽지 않고, 이름/가격을 직접 입력해서 담는 기능 제공

## 아직 없는 기능 (의도적으로 보류)

**매장별 실시간 재고 확인은 이번 버전에 없습니다.**
다이소몰 검색은 완전히 열려있는 API라 안전하게 자동화할 수 있었지만, 매장 재고 조회는
요청마다 30초짜리 암호화된 1회용 토큰이 필요한 **봇 차단(anti-bot) 보호**가 걸려있는 걸
확인했습니다. 이건 로그인과 무관한, "진짜 브라우저로 접속했는지" 검증하는 장치라서 이걸
흉내 내서 자동 조회하는 기능은 만들지 않았습니다. 재고 기능은 나중에 다른 방식(예: 다이소몰
공식 "매장 상품 찾기" 페이지로 바로 연결해주는 버튼 등)으로 따로 논의해서 추가하면 됩니다.

## 폴더 구조

```
daiso-cart-app/
├── api/
│   ├── search.js     ← 다이소몰 검색을 대신 호출해주는 서버 코드 (Vercel 서버리스 함수)
│   └── cart.js        ← 친구와 같이 쓰는 공유 장바구니를 저장/조회하는 서버 코드
├── public/            ← 실제로 폰 화면에 보이는 부분
│   ├── index.html
│   ├── style.css
│   ├── app.js
│   ├── manifest.json  ← PWA 설정 (앱 이름, 아이콘 등)
│   ├── sw.js           ← 오프라인에서도 화면이 뜨게 해주는 서비스워커
│   └── icons/icon.svg
└── package.json
```

왜 "서버"가 따로 필요한가요? → 브라우저(휴대폰)에서 다이소몰 서버를 직접 부르면 다른
사이트에서 왔다는 이유로 막힐 수 있어서, 중간에 우리 서버(`api/search.js`)가 대신
요청해주고 결과만 돌려주는 구조입니다. 이 서버는 결과를 10분간 기억해뒀다가 같은 검색어가
오면 다이소몰에 다시 묻지 않고 바로 돌려줘서, 다이소몰 서버에 너무 자주 요청하지 않도록
해뒀습니다.

## 무료로 배포하기 (Vercel) — 코딩 몰라도 되는 방법

터미널이나 코딩 지식 없이, **GitHub 웹사이트 + Vercel 웹사이트**만으로 할 수 있는 방법입니다.
전체 과정 10~15분 정도 걸려요.

### 1단계. GitHub 계정 만들기

1. https://github.com 접속 → 오른쪽 위 **Sign up** 클릭
2. 이메일/비밀번호 입력하고 가입 (이미 계정 있으면 로그인만 하면 됩니다)

### 2단계. 새 저장소(repository) 만들고 파일 올리기

1. 로그인 후 오른쪽 위 **+** 버튼 → **New repository** 클릭
2. Repository name에 `daiso-cart-app` 입력 → **Public** 선택 → **Create repository** 클릭
3. 저장소가 만들어지면 **"uploading an existing file"** 링크(또는 `Add file` →
   `Upload files`)를 클릭
4. 내 컴퓨터의 `daiso-cart-app` 폴더 안에 있는 **모든 파일과 폴더**
   (`api`, `public`, `package.json`, `README.md`)를 통째로 끌어다 놓기(drag & drop)
   - 폴더째 끌어다 놓아도 GitHub가 내부 구조를 그대로 올려줍니다
5. 아래쪽 **Commit changes** 버튼 클릭 → 업로드 완료

### 3단계. Vercel 가입하고 이 저장소 연결하기

1. https://vercel.com 접속 → **Sign Up** → **Continue with GitHub** 선택해서
   방금 만든 GitHub 계정으로 가입/로그인
2. 로그인되면 **Add New...** → **Project** 클릭
3. 방금 올린 `daiso-cart-app` 저장소가 목록에 보이면 **Import** 클릭
4. 설정 화면이 뜨면 거의 그대로 둬도 됩니다 (Framework Preset: "Other"로 자동 인식되면 OK)
5. **Deploy** 버튼 클릭 → 1~2분 기다리면 완료
6. "Congratulations!" 화면과 함께 `https://daiso-cart-app-xxxx.vercel.app` 같은
   주소가 생깁니다. 이게 내 앱 주소예요.

### 4단계. "친구랑 같이 쓰기" 기능 켜기 (Vercel Storage 연결)

이 단계를 건너뛰어도 앱은 잘 작동하는데, 👥 공유 버튼만 동작하지 않습니다(에러 없이
그냥 동기화가 안 됨). **이미 만든 같은 Vercel 계정 안에서** 저장 공간을 하나 켜주면 됩니다
(다른 사이트 가입 아님):

1. 방금 배포한 프로젝트 화면에서 위쪽 **Storage** 탭 클릭
2. **Create Database** → **KV** (또는 Upstash가 제공하는 Redis) 선택
3. 이름은 아무거나(예: `daiso-cart-kv`) 입력하고 **Create** 클릭
4. 만들어지면 **Connect to Project** 또는 자동으로 연결 여부를 물어보면 방금 만든
   `daiso-cart-app` 프로젝트 선택 → 연결
5. 프로젝트 **Deployments** 탭 → 맨 위 배포 옆 `...` 메뉴 → **Redeploy** 클릭
   (저장소를 새로 연결한 뒤엔 한 번 다시 배포해줘야 적용됩니다)

이제 앱에서 👥 버튼을 누르면 공유 링크가 생기고, 그 링크를 받은 친구도 같은 목록을
보게 됩니다.

> 참고: 공유 링크에는 임의의 방 코드(예: `?room=AB12CD`)가 들어있어요. 그 링크를 아는
> 사람은 누구나 그 장바구니를 보고 수정할 수 있으니, 꼭 필요한 사람에게만 공유하세요.
> 또 거의 동시에 두 사람이 수정하면 나중에 저장된 쪽이 반영됩니다(2명이 쓰는 용도라
> 보통 문제 없어요). 30일 동안 아무도 안 건드리면 그 공유 목록은 자동으로 사라집니다.

### 5단계. 나중에 내용을 수정하고 싶을 때

1. GitHub 저장소 페이지에서 수정하고 싶은 파일 클릭 → 연필 아이콘(Edit) 클릭 →
   내용 고치고 **Commit changes**
2. 저장만 하면 Vercel이 자동으로 몇 분 안에 다시 배포해줍니다 (따로 할 일 없음)

## 휴대폰에 앱처럼 설치하기 (PWA)

배포된 주소(`https://xxxx.vercel.app`)에 휴대폰 브라우저로 접속한 뒤:

**아이폰(Safari)**
1. 공유 버튼(네모에 화살표) 탭
2. **홈 화면에 추가** 선택

**안드로이드(Chrome)**
1. 오른쪽 위 점 3개(⋮) 메뉴 탭
2. **홈 화면에 추가** 또는 **앱 설치** 선택

홈 화면에 아이콘이 생기고, 탭하면 주소창 없이 앱처럼 열립니다.

## 알아두면 좋은 점

- 검색 결과가 안 뜨면 다이소몰 서버가 잠깐 불안정한 걸 수 있어요. 이럴 땐 "직접
  입력해서 담기"로 이름/가격을 손으로 입력해서 담으면 됩니다.
- 👥 공유를 켜지 않은 상태(기본값)에서는 장바구니 데이터가 그 휴대폰/브라우저에만
  저장됩니다. 👥 버튼을 눌러 친구와 공유하면 그때부터는 서버(Vercel Storage)에도
  저장돼서 두 사람이 같은 목록을 봅니다.
- 다이소몰이 검색 API 형식을 바꾸면 검색 기능이 일시적으로 안 될 수 있는데,
  그 경우에도 `api/search.js`의 응답 해석 부분만 손보면 됩니다
  (`docs = resultArr.find(...)` 부분).
